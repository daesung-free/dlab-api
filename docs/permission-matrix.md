# 사용자 권한 매트릭스 (초안)

> **확정 전 초안입니다.** 요구사항정의서가 RBAC 5단계만 정의하고 *"상세 권한 매트릭스는
> 별도 시트 참조"*라고 하는데 **그 시트가 어디에도 없습니다.** 그래서 개발팀이 화면과
> 업무 흐름을 근거로 채워 넣었습니다 — 검토 후 확정 부탁드립니다.
>
> 확정되면 화면 접근 제어와 서버 권한 검사가 **이 표와 1:1로** 맞춰집니다.

## 역할 5종

| 역할 | 누구인가 |
|---|---|
| **본사** (SUPER_ADMIN) | 전 지점을 보고 고칠 수 있는 최상위 |
| **지점관리자** (BRANCH_ADMIN) | 자기 지점 전 기능 |
| **담당선생님** (TEACHER) | 사감. 담임을 맡고 승인 에스컬레이션 대상이 된다 |
| **행정** (STAFF) | 행정선생님. 데스크 업무(급식·수납 조회 등) |
| **조회전용** (READONLY) | 보기만. 아무것도 못 고친다 |

## 권한 4단계

| 표기 | 뜻 |
|---|---|
| **전체** | 조회 · 등록 · 수정 · 삭제 |
| **담당분만** | 자기 반 · 자기 담당 학생에 대해서만 |
| **조회만** | 볼 수는 있고 못 고친다 |
| **없음** | 메뉴 자체가 안 보인다 |

> **2026-09-28 수정 — 급식, 조회 전용: 「없음」 → 「조회만」.**
> 조회 전용의 뜻이 「보기만」이라, 급식 신청 현황·마감일을 못 보면 그 권한으로 급식 화면이
> 통째로 빈다. 실제로 서버는 조회만 열어 두었고 쓰기(마감 등록·정책 변경·취소)는 막혀 있다.
> 결제·취소를 못 하는 것은 그대로다.

> **2026-10-14 수정 — 특강(담당선생님): 「담당분만」 → 「없음」.**
> 특강 출석 체크는 행정 업무이고 서버 API 도 관리자만 열려 있습니다. 더해서 특강 출석부는
> **반 단위가 아니라 신청자 전원**이라, 담당선생님에게 열면 자기 반 밖 학생까지 보입니다 —
> 「담당분만」으로는 표현되지 않는 범위입니다. **담당선생님이 특강 출석을 찍는 운영이라면
> 알려주십시오** — 그때는 읽기·출석 체크만 열고 개설·정원·취소는 관리자에 둡니다.

> **2026-10-14 수정 — 성적(조회 전용): 「조회만」 → 「없음」.**
> 성적 읽기 API 가 조회 전용에 하나도 열려 있지 않습니다(양식·학생 성적·추이 전부 차단).
> 메뉴만 남기면 들어갔는데 빈 화면이라 「고장」으로 읽힙니다. 성적은 **장학 취소 판정의
> 근거**이고 조회 전용의 실사용 범위가 아직 정해지지 않아 좁은 쪽으로 두었습니다 —
> **조회 전용이 성적을 봐야 한다면 알려주십시오.**
>
> 같은 날 **담당선생님의 성적 「담당분만」은 실제로 그렇게 동작하도록 고쳤습니다.** 정정 API 는
> 열려 있었는데(0826 회신 *"처음 입력은 학생, 이후 수정은 직원을 통해서"*) **시험 양식 목록이
> 본사 전용이어서 화면이 뜨지 않았습니다.** 양식 읽기를 지점 소속에 열고, 양식을 만들고
> 고치는 것은 본사에 그대로 두었습니다.

## ★ 확인 부탁드리는 것 4가지

나머지는 이견이 적을 것으로 보고, **판단이 갈릴 만한 것만** 추렸습니다.

### 1. 할인·장학 설정 — 지점은 조회만?

할인은 **실제 청구 금액을 바꾸는 값**이라 좁게 잡았습니다.

- 지점에서 재량으로 할인을 주는 운영이 있다면 → **지점관리자도 「전체」**로 바꿔야 합니다

### 2. 기초 설정(학과·과정·반) — 지점은 조회만?

이 항목만 **지금 시스템과 초안이 다릅니다.** 현재 서버는 지점관리자도 등록·수정할 수 있습니다.

학과·과정은 **지점·연도 단위 데이터**라 지점이 자기 것을 만드는 게 자연스러워 보입니다.
초안이 좁게 잡은 쪽으로 판단됩니다.

- 지점이 만들어도 된다면 → **「전체」**로 바꾸고 지금 동작을 그대로 둡니다
- 본사만 관리한다면 → 서버 쪽 권한을 조이겠습니다

### 3. 엑셀 마스킹 해제 — 지점관리자까지?

명단을 내려받을 때 **연락처·생년월일을 가리지 않고** 받는 권한입니다.

지점관리자는 학부모에게 직접 연락하는 것이 업무라 포함시켰습니다.

- 개인정보 관리 기준상 **본사만** 열어야 한다면 알려주십시오

### 4. 성적 — 행정은 정말 「없음」입니까?

표는 행정을 「없음」으로 두었는데 **서버는 조회와 모의고사 엑셀 업로드가 행정에 열려 있습니다.**
어긋난 곳이라 손대지 않고 남겨 두었습니다 — **월례고사 성적을 누가 올리는지**가 정해지지
않았고, 그 답이 이 칸을 정합니다.

- 행정이 엑셀을 올린다면 → **「전체」**(또는 업로드만)로 바꾸고 메뉴에 성적을 넣습니다
- 담당선생님이 올린다면 → 행정은 「없음」 그대로 두고 서버 권한을 조이겠습니다

## 참고 — 이미 정해져 있는 것

아래는 이 표와 별개로 **이미 확정·구현된 규칙**입니다. 매트릭스와 충돌하지 않습니다.

- **공지 작성 권한**은 역할이 아니라 소속으로 갈립니다 — 전체공지는 행정선생님, 반공지는
  담당선생님(회의 확정사항)
- **개인정보(전화·주소·생년월일)** 가 포함된 응답은 상위 관리자만 원본을 봅니다.
  엑셀 다운로드는 **마스킹이 기본**입니다
- **지점 간 격리**는 역할과 무관하게 항상 걸립니다 — 남의 지점 데이터는 조회 자체가 막힙니다
- **직원 계정 승인**은 본사만 합니다(2026-09-08 확정). 지점이 만든 계정은 승인 전까지
  로그인이 막힙니다
