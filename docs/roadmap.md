# D.Lab 개발 로드맵 — 단계별 작업 분류

> **언제 읽나** — "다음에 뭘 구현하지?", "이거 지금 착수해도 되나?"를 판단할 때.
> **함께 보는 문서** — 엔드포인트 상세는 `docs/api-spec.md`, 도메인별 블로커는 `docs/domain-map.md`,
> 키오스크 계약은 `docs/dsa-compat.md`, 테이블 설계 근거는 `docs/schema-guide.md`.

## 편성 원칙

1. **블로커 없는 것부터.** §4 블로커에 걸린 도메인은 임의 가정으로 진행하지 않는다 (CLAUDE.md §6-3).
2. **외부 연동은 도메인 로직 안정 후.** Zyxel·더프리미엄·PG·채팅 SDK는 해당 도메인이 굳은 뒤 붙인다 (CLAUDE.md §6-2).
3. **화면 선개발 금지.** API·스키마 확정 전에 화면부터 만들지 않는다 (CLAUDE.md §6-1).

범례: ✅ 착수 가능 · 🟡 부분 착수 · ❌ 블로커 대기

## Phase 0 — 기반 ✅

모든 것의 선행. 블로커 없음.

**공통 계층**
- `ApiResponse<T>` · `ErrorCode` · `GlobalExceptionHandler`
- JWT 인증 + **RBAC 5단계** (`SUPER_ADMIN` / `BRANCH_ADMIN` / `TEACHER`(담당선생님·사감) / `STAFF`(행정선생님) / `READONLY`)
- 지점 필터 공통 처리 (전 지점 조회는 상위 관리자만)
- 요청/응답 로깅

**DSA 호환 예외 구획** — 반드시 Phase 1 전에
- `/auth/**`·`/kiosk/**` 전용 응답 객체 (`{code, message, data, …}`)
- 전용 예외 핸들러 (`ApiResponse` 래퍼·`GlobalExceptionHandler` **적용 제외**)
- `BusinessException` → DSA `code` 매핑 테이블

**Flyway V1** — 마스터
- 지점 · **학생 2단**(사람 `student` + 등록건 `student_enrollment`) · 학부모
- 좌석/구역 · **교시 마스터**

**Flyway V2** — 출결
- `attendance_logs`(태깅 원장) · `attendance_daily`(일자 집계) · `absence_requests`

**기타**
- `YearlySnapshotService` 골격 — 의존 순서 `department → course_type → class_group → curriculum → penalty_item → tuition`, **단순 `INSERT SELECT` 금지**
- springdoc-openapi → `docs/openapi.yaml` 자동 생성 (CLAUDE.md §6-4)

> **교시 마스터 주의** — 시안(`07_admin_plan`, `plan-1~3`)에서 시간까지 확정됐다. 0교시 07:40 ~ 야3 23:20, 점심·저녁·종례·간식 포함 14블록. 주말은 구성이 다르다.
> **출결 판정(`code 113`·`122`)과 학습계획 그리드가 같은 마스터를 쓴다.** 두 번 만들지 말 것.

## Phase 1 — 키오스크 DSA 호환 25개 ✅ ★

**블로커 없음. 크리티컬 패스.** 학생이 매일 태깅하는 물건이라 컷오버 시점에 반드시 동작해야 한다.
앱·관리자 웹 어느 쪽에도 의존하지 않아 **혼자 완결된다.**

| 그룹 | 개수 | 상태 | 비고 |
|---|---|---|---|
| 인증 (`/auth/token` `/refreshToken`) | 2 | ✅ | MD5(`yyyyMMdd`+secret), Redis 9일/99일, **자정 경계 처리** |
| 학생·지점·학부모 | 4 | ✅ | 원생MST/RLS 확보. `p_gb`는 F/M만 (기타 보호자 매핑 주의) |
| **출결** (`setAttendStd` `setReAttendProc`) | 2 | ✅ | 7종 상태 + 분기코드 6개 + `113` 2-phase 왕복 |
| 통계·상세 | 6 | ✅ | `attendance_daily`에서 집계 |
| 급식·상벌점·수납 조회 | 4 | ✅ | 레거시 확보. `getReceiptInfo`는 `TB_RECEIVE_MST`와 필드 일치 |
| 좌석 | 4 | 🟡 | `state` 값 목록 미상 |
| 사유 조회 | 1 | 🟡 | `reg_gn` 값 목록 미상 |

미상 값 2건은 **대성전산에 물을 필요 없이 키오스크 클라이언트 소스의 파싱 코드**에서 확정 가능하다.

**`setAttendStd`가 이 프로젝트 출결의 심장이다.**
- 상태 7종: `S`등원 `T`하원 `A`지각 `D`외출 `N`사유외출 `C`조퇴 `R`복귀
- 분기코드가 **최상위(`121`·`130`)와 `data` 내부(`122`·`113`·`126`·`128`·`129`)로 갈려서** 온다
- `113`은 **stateless 2-phase** — 서버가 왕복 사이 상태를 들고 있으면 안 된다
- **응답을 "정리"하면 키오스크가 깨진다** (`data` 이중배열, `"N시간 M분"` 문자열, `meal_gb` 비대칭 등)

## Phase 2 — 회원·기초 마스터 ✅

모든 도메인의 뿌리. 블로커 없음. **Phase 1과 병렬 가능.**

**관리자 웹**
- 학생 검색(12개 조건) · 신규 접수 · **학번 채번** `year + %04d` (예: `2026-0001`), `UNIQUE(year, student_no)`
- 반 배정 · **반별 담임(담당선생님) 지정**
- 직원·강사 계정, 권한 관리, 지점별 접근 제어

**기초 관리**
- **교시·시간 편집 (지점 공통)** · 학과 · 전형 · 과정 · 강의실 · 사물함 · 장학
- 배정관리 (기숙사 · 사물함 · 독서실)
- **전년도 복사** 실동작

> **반에 담임을 지정하면 학생 배정 시 방화벽 승인자가 자동 결정된다** (Phase 5 선행조건).
> 학생별로 승인자를 따로 지정하는 화면은 만들지 않는다 (CLAUDE.md §3).

## Phase 4 — 앱 온보딩·인증 🟡

Phase 2의 `user` 도메인이 선행.

온보딩 4단계: **회원가입 → OT(대면) → 학부모 인증(알림톡) → 정기일정 등록**

**앱**
- 휴대폰 인증
- **학생 가입** — 승인제. `PENDING` → 관리자 승인 → `ACTIVE`. **중간 상태 없음**, 승인 전 앱 접근 전면 차단
- **학부모 가입** — 학생 고유ID만 맞으면 승인 없이 즉시 `ACTIVE`. **관계 검증 안 함**(클라이언트가 인지·감수한 리스크, 추가 검증 로직 만들지 말 것)
- 로그인/토큰 (refresh·블랙리스트 Redis)
- 마이페이지 — 학생 본인 고유ID 노출(학부모 연결용 유일 수단)
- **자녀 전환** — 계정 1개 + 자녀 N (자녀 수만큼 계정 분리 아님)

**앱 홈** (`stu-1~3`, `par-1~3`)
- 프로필 · 3지표(벌점/모의고사 등급/순공시간) · 퀵메뉴 8개 · 배너 알림

**관리자 웹**
- 학생 가입 승인

⚠️ **내신 입력 양식 미정** — 학생 가입 흐름이 여기서 막힌다. 모의고사는 더프리미엄 자동조회라 무관.
⚠️ **순공시간 산출 정의(I-6)** — 홈 3지표에 필요.

## Phase 5 — 승인 워크플로우 ❌ ★

**이 프로젝트의 도메인 본질**이다 (CLAUDE.md §1 — 학생 행위 → 학부모 승인 → 자동 처리의 3자 상태머신).

- **`approval` 공통 라우팅** — 사유신청 · 정기일정 · 방화벽이 **전부 여기를 탄다**.
  `firewall` 안에 두면 사유신청에서 같은 로직을 또 짜게 된다
- 타임아웃 **10분** + 담당선생님 에스컬레이션
- **3케이스 문구 분기** — 2번("승인 시간이 **지나** 담임이 승인")과 3번("승인 시간이 **남았지만** 담임이 먼저 승인")을 **절대 같은 메시지로 통일하지 말 것**
- 상태 전이는 **원자적으로**. 케이스 판별은 `승인시각` vs `신청시각 + 타임아웃`
- `firewall` 신청/승인 → **Zyxel Nebula 연동은 로직 안정 후**
- `schedule` 정기일정 — 승인은 학부모 앱에서만 (관리자 웹 관여 없음)

| 블로커 | 내용 |
|---|---|
| I-12 | 항목별 승인 주체 매트릭스 (`PARENT`/`TEACHER`/`AUTO`) |
| I-20 | 타임아웃 세부·사전지정 |
| E-1 | Zyxel 크레덴셜, 제어 단위(학생·단말 vs 정책·그룹) |

> 미해결 설계 질문: **학부모가 부·모·기타 3명일 수 있다.** `approver_type=PARENT`가 누구인지, 아무나 승인하면 되는지 정의가 없다 (요구사항정의서 어디에도 없음 — 신규 이슈 등록 필요).

## Phase 7 — 성적·학습관리·상담 ❌

시안이 가장 두꺼운 영역인데 블로커도 가장 많다.

**`grade`**
- 회차별 성적표(원점/표준/백분위/등급) · 내용영역·세부단원 정답률(본인 vs 전국) · 채점표 · 평가요소 · 동점자 · 지원가능대학 · 정시 반영비율
- **학생/학부모 노출 범위 분리** — 채점표·평가요소·동점자는 **학부모에게 노출 금지**. 권한별 DTO 분리 필수
- 더프리미엄 엑셀 업로드 + API 자동조회 → 로직 안정 후

**`learning-plan`**
- 주간 그리드(교시 × 요일) · 일간 이행 체크 · **3단계 입력**(학습형태 → 과목 → 교재·내용)
- 학습형태 4종(수업/인강/자습/**테스트**), 과목 5종(국/수/영/탐1/탐2)
- 관리자: 교사 편집 · 주말 의무자습 잠금 · 선택목록 편집 · 이행률 · 과목·형태별 비율

**`daily-routine` · `daily-report`** — 월별 루틴 세팅(전월 복사) · 결과 입력 → 상벌점 연동 · 순공 랭킹 집계

**`consult`** — 상담일지(유형 5종 · 방식 3종) · 성적 근거 자동 첨부 · **공유범위 3단계**(`NONE`/`SUMMARY`/`FULL`) · 입학예약 상담부터 연속 이력

## Phase 8 — 알림·공지·메시지 ❌

- **`notification`** — 개별·단체 발송, 자동발송 템플릿. **모든 템플릿에 `{학생명}` 변수 필수** (다자녀 학부모 혼동 방지)
- **스케줄러: 미등원 알림** — 등원시간 정각에 배치 실행 → 태깅 기록 **없는** 학생 필터 → 학부모 카카오 알림톡. 사전 사유 제출자 제외
- `notice` — 공지(**작성 권한 역할별 분기**: 전체공지=행정선생님, 반공지=담당선생님. 조회는 관리자 전체 공유) · 질의응답 · 설문
- `chat` — SDK 후보 프로토타입 → 클라이언트 선택 → 연동 + **메시지 원본 우리 DB 동기화**

> **미등원 알림은 "이벤트가 없었음"을 감지하는 유일한 유형이다.** 요청 리스너만으로는 구현 불가 — 별도 스케줄러 컴포넌트가 필요하다.

| **E-5** | 카카오 발신프로필·템플릿 **사전심사** — 리드타임 길어 **조기 착수 유리** |
| I-4 | 알림톡/푸시 전체 문구 |
| I-14 | 알림톡 단독 vs FCM 병행 |
| E-6 | 채팅 SDK 선정 |

## Phase 9 — 입학·교무·부가 ❌

- **`admission` 6단계 파이프라인** — 신규예약(구글폼) → 방문상담 → 입학기준 확인 → 좌석·장학 배정 → 입학확정 → **재원생 전환**. 단계 전환 시 문자 자동발송
- 대기자 관리 (순번 알림, 원클릭 전환 + 앱 초대)
- 특강·설명회 · 실적 관리
- **신상기록부** (입학 필수, 학년별 폼 분기, PDF 출력)

## 의존 관계

```
Phase 0 ─┬─ Phase 1 (키오스크) ──┬─ Phase 3 (출결 표면)
         │                        │
         └─ Phase 2 (회원·기초) ──┴─ Phase 4 (앱 온보딩) ── Phase 5 (승인) ★
                    │
                    ├─ Phase 6 (결제·급식)
                    ├─ Phase 7 (성적·학습·상담)
                    ├─ Phase 8 (알림·공지·채팅)
                    └─ Phase 9 (입학·교무)   →  컷오버
```

- **Phase 1과 2는 병렬 가능** (Phase 0만 끝나면)
- **Phase 6~9는 서로 독립** — 블로커 풀리는 순서대로 붙이면 된다

## 착수 가능 요약

|---|---|---|
| 0 기반 | 없음 | ✅ |
