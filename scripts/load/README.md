# D:VOCA 부하 테스트

v1 9장 비기능 요구에 대한 스크립트다.

> *"재원생은 2,000명에서 **5,000명 이상**까지 늘 수 있고, **최대 50%가 동시 접속**할 수 있다
> (약 2,500명). **시험 시작과 제출 API에 부하 테스트**를 한다.
> 서버는 업체가 준비하므로 **성능은 그 서버 사양에 따른다**."*

## ★★ 먼저 한 것 — 쿼리 수 고정

**부하를 걸기 전에 쿼리 수를 테스트로 고정했다**(`VocabExamQueryCountTest`).
문항마다 조회가 도는 구조면 **서버를 키워도 같은 비율로 늘어나** 사양으로 덮을 수 없다.

실측으로 **N+1 두 개를 찾아 고쳤다.**

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| `start` (문항 4 → 20) | 17 → **49** | 12 → **28** |
| `submit` (문항 4 → 20) | 11 → **43** | 8 → **24** |

- `start` — 보기 추출이 **문항마다** `findByUnitNo` 를 불렀다 → 이미 읽은 범위를 유닛별로 묶어 쓴다
- `start` — 전체 단어(2,000건)를 **항상** 읽었다 → **폴백에 들어갈 때만** 읽고, 그 응시 안에서 재사용한다
- `submit` — 채점이 **단어마다** `vocab_meaning` 을 조회했다 → 한 번에 읽어 묶는다

**지금은 문항당 쿼리 증가가 1**이고 그건 **원장 쓰기(답안 INSERT · 채점 UPDATE)라 피할 수 없다.**
테스트가 **상한이 아니라 기울기**를 보므로, 누가 조회를 하나 더 넣으면 기울기가 2가 되어 CI 가 잡는다.

## 실행

```bash
k6 run -e BASE_URL=https://api.example.com -e TOKENS=tokens.json scripts/load/dvoca-exam.js
```

`tokens.json` 은 **테스트 계정** Access Token 배열이다.

```json
["eyJhbGciOi...", "eyJhbGciOi...", "..."]
```

⚠️ **실제 학생 토큰을 쓰지 말 것.** 응시 기록은 **영구 보존**이라(v1 9장) 그 학생 기록에
부하 데이터가 섞이고, **지울 수단이 없다**(미제출 응시도 지우지 않는 구조다).

⚠️ **한 계정으로 2,500 VU 를 돌리지 말 것.** 「진행 중인 응시 재사용」에 걸려 전원이 같은
응시를 공유하고, 그러면 `start` 가 문항을 만들지 않아 **측정하려던 경로가 돌지 않는다.**
토큰을 VU 수만큼 나눠 쓴다.

## ★★ 언제 돌리는가 — 지금이 아니다

**운영 사양에서 돌려야 의미가 있다.** 인프라가 개발 서버를 그대로 운영으로 전환하는
방식이라(CLAUDE.md §3) **컷오버 시점**이 맞다. 개발 서버에서 나온 숫자는 운영 성능이 아니다.

⚠️ `thresholds` 의 3초·1% 는 **합의된 기준이 아니다.** v1 9장이 *"성능은 그 서버 사양에
따른다"* 로 뒀고 운영 사양이 정해지지 않았다 — **「이보다 느리면 학생이 기다린다」는
체감 기준**일 뿐이다. 사양이 정해지면 디랩과 맞춰 고칠 것.

## 아직 안 한 것 — JDBC 배치

쓰기가 문항당 1개씩 나므로 **묶으면 왕복이 줄어든다.** 그런데 켜지 않았다.

- ⚠️ **INSERT 는 배치가 안 된다.** 엔티티가 `GenerationType.IDENTITY` 라 Hibernate 가
  **키를 받으려고 매 건 실행**한다 — `batch_size` 를 켜도 `start` 쪽은 그대로다.
  바꾸려면 시퀀스 전략으로 옮겨야 하고, 그건 **전 테이블에 걸친 변경**이다.
- UPDATE(`submit`)는 묶인다. 다만 `order_updates` 와 함께 **앱 전체 쓰기 경로**에
  영향이 가는 설정이라, 실부하로 검증하지 않고 켜는 것은 위험하다.

**부하를 돌려 `submit` 이 실제로 걸리면** 그때 `spring.jpa.properties.hibernate.jdbc.batch_size`
와 `order_updates` 를 켜고 다시 재는 순서가 맞다.
