# 전 지점 좌석 2,140석 적재

디랩이 2026-10-22 에 확정해 준 전 지점 좌석배치를 **운영 API 로** 넣는다.
근거는 `md/좌석배치/개발자_전달_좌석배치확정_1023.md`(0-1 집계표 · 5장 번호표)와
배치표 PNG 39장이다.

```
seat-layout.json        39구역 · 2,140석의 구역·격자 정의 (적재 입력)
load-seat-layout.mjs    적재 스크립트 — 기본이 미리보기다
build-seat-layout.py    PNG → seat-layout.json 생성기 (재생성용)
```

## 왜 API 인가 — SQL 로 넣지 말 것

`seat_master.kiosk_seat_cd` 가 **등록 시점에 계산돼 저장된다**(`KioskCodeTranslator`).
동탄 별관 1번은 `1001` 로 내려가야 하는데, 마이그레이션으로 밀어 넣으면 그 변환이 돌지
않아 **단말에 내려가는 번호가 어긋난다.** 화면과 DB 는 멀쩡해서 원인을 찾기가 매우 어렵다.
지점 안 키오스크 번호 충돌 검사도 서비스에만 있다.

## 돌리는 법

```bash
# ① 계획만 본다 — 서버·토큰 없이 돈다
node scripts/seat-layout/load-seat-layout.mjs --plan

# ② 미리보기 — 서버에 조회만 해서 무엇을 만들고 무엇을 건너뛸지 본다
ADMIN_TOKEN=<본사 계정 Access Token> BASE_URL=https://<운영> \
  node scripts/seat-layout/load-seat-layout.mjs

# ③ 한 지점만 먼저
ADMIN_TOKEN=... BASE_URL=... \
  node scripts/seat-layout/load-seat-layout.mjs --apply --branch 분당

# ④ 전 지점 적재 + 검산
ADMIN_TOKEN=... BASE_URL=... \
  node scripts/seat-layout/load-seat-layout.mjs --apply
```

- ⚠️ **토큰은 환경변수로만 받는다.** 없으면 바로 멈춘다(`--plan` 제외).
- ⚠️ **권한은 `SUPER_ADMIN`** 이 필요하다 — 11개 지점을 한 번에 돌린다.
- **멱등하다.** 이미 있는 구역·좌석은 건너뛰고 몇 건을 건너뛰었는지 보고한다.
- **한 구역씩 처리하고 실패하면 그 구역에서 멈춘다.** 절반 들어간 상태를 만들지 않는다.
  고친 뒤 그대로 다시 돌리면 된다.
- 한 격자가 **반쯤** 들어가 있으면 메우지 않고 멈춘다 — 번호가 어디서 끊겼는지 모르는 채
  이어 붙이면 그 뒤가 전부 밀린다.

## ★ 동탄 별관 — 만들지 않는다

별관 `building` 행은 **운영에 이미 있다**(`code='2'` · `seat_cd_offset=1000`).
스크립트는 그것을 **찾아 쓰기만** 하고 없으면 멈춘다.

- **코드로 찾지 않는다.** 운영 별관 코드가 지점마다 다르다(동탄 `'2'` · 대구 `'SUB'`).
  `main` 플래그(= `seat_cd_offset == 0`)로 가른다.
- `seat_cd_offset` 이 1000 이 아니면 멈춘다 — 그 값은 **만든 뒤 바꿀 수 없고**,
  잘못 만들면 그 관의 키오스크 번호가 영구히 어긋난다.
- `seat-layout.json` 의 별관 좌석번호는 **내부 번호(1~34 · 101~141 · 201~225)** 다.
  배치표의 `1001~1034` 는 offset 이 적용된 키오스크 번호이고 서버가 만든다.

## 검산

`--apply` 가 끝나면 `GET /admin/seats/layout` 으로 되읽어 비교한다.

- **구역별** 좌석 수 39건
- **형태별**(교실형 1,637 · 집중형 449 · 1인실 54)
- **지점별** 12건(동탄은 본관·별관을 나눠 센다)
- 합계 2,140

★ **합계만 맞추지 않는다.** 한 구역을 덜 넣고 다른 구역을 더 넣어도 2,140 은 그대로다.
집계표 값은 `load-seat-layout.mjs` 안에 **데이터와 따로** 박아 뒀다 —
`seat-layout.json` 안의 합계로 대조하면 그 파일을 고쳤을 때 언제나 자기 자신과 맞는다.

## seat-layout.json 을 다시 만들려면

```bash
pip3 install pillow
python3 scripts/seat-layout/build-seat-layout.py            # md/ 의 PNG 를 읽는다
python3 scripts/seat-layout/build-seat-layout.py --png-dir <경로>
```

입력 PNG 는 `md/좌석배치/좌석배치표/` 에 있고 **`md/` 는 git 밖**이다. 그래서 결과
JSON 을 커밋해 둔다(좌석 번호·좌표뿐이라 개인정보가 아니다).

생성기가 하는 일:

- **빈칸(통로·기둥)을 픽셀에서 읽는다.** 2,140석에 걸친 빈칸이 1,000칸이 넘어
  손으로 옮기면 한 칸만 어긋나도 뒤의 번호가 전부 밀린다.
  디랩 답변(C-2)대로 **하늘색(통로)과 회색(기둥)을 구분하지 않는다** — 둘 다 「좌석 없음」.
- **좌석 수를 3중으로 검산한다**: 격자별 → 구역별(시트2) → 지점별·전체(0-1 집계표).
  하나라도 어긋나면 생성이 멈춘다.
- **번호 앵커 96개를 대조한다.** 좌석 수만으로는 방향을 검증할 수 없다 —
  가로 역방향을 정방향으로 넣어도 **좌석 수는 똑같이 맞고 번호만 거꾸로 붙는다.**
  그래서 배치표에서 눈으로 읽은 「번호 → 칸 위치」를 적어 두고,
  서버 `SeatMasterAdminService.plan()` 과 같은 순서로 번호를 매겨 대조한다.

사람이 판단한 것은 둘뿐이다 — **격자를 어디서 자르는가**와 **번호가 붙는 방향**.
둘 다 `build-seat-layout.py` 의 `GRIDS` 한 곳에 모여 있다.

## 격자를 쪼갠 구역 18개

한 구역에 격자가 여러 개인 곳이다. 아래쪽에 가로로 한 줄이 따로 붙어 있거나,
번호가 중간에 방향을 바꾸는 곳이다.

| 구역 | 격자 | 왜 |
|---|---|---|
| 광명 C | 6 | 가로줄 5개가 전부 오른쪽→왼쪽이고 264~287 블록만 세로 우선 + 가로·세로 역방향 |
| 목동 A · 목동 C | 4 | 본체 + 오른쪽 세로블록 + 아랫줄 2개 |
| 동탄 본관 A · 김포 A · 김포 C | 3 | 1~10 이 맨 왼쪽 세로줄, 그다음이 아랫줄, 그다음이 본체 |
| 동탄 본관 B·C · 부천 A · 이매 B·C · 광명 A · 목동 B·D · 송파 A·B·C · 대전 A | 2 | 본체 + 방향이 다른 한 덩어리 |

## ★ 역방향 구역

```
대구 A · 대구 C     1번이 오른쪽 끝 → 왼쪽으로 증가        reverseX
동탄 별관 C         1201 이 오른쪽 아래 → 왼쪽 위로        reverseX + reverseY
송파 A·B·C 아래 블록 오른쪽 아래에서 거꾸로 올라온다        reverseX + reverseY
광명 C 264~287      같음                                   reverseX + reverseY
대전 A·B            아래 줄에서 위로 올라간다               reverseY
대전 C              줄마다 오른쪽에서 왼쪽                  reverseX
```
